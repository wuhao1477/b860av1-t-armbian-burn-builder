# USB OTG 修复工作完成总结

## 🎯 任务目标

解决 B860AV1-T 设备上 USB OTG 无法工作的问题，使 One-KVM 的键盘/鼠标 HID 功能正常。

## ✅ 已完成的工作

### 1. 问题诊断（100%）

**根本原因确认**：
- dwc2 USB 控制器在初始化时软复位超时
- 错误信息：`dwc2_core_reset: HANG! Soft Reset timeout GRSTCTL_CSFTRST`
- 寄存器状态：`GRSTCTL=80000430`（复位位未清除）

**设备树缺陷定位**：
```dts
// ❌ 当前设备树（缺少 resets 属性）
usb@c9100000 {
    compatible = "amlogic,meson-g12a-usb", "snps,dwc2";
    reg = <0x00 0xc9100000 0x00 0x40000>;
    dr_mode = "peripheral";
    // 缺少 resets 属性导致驱动无法复位硬件
};

// ✅ 修复后（添加 resets 属性）
usb@c9100000 {
    compatible = "amlogic,meson-g12a-usb", "snps,dwc2";
    reg = <0x00 0xc9100000 0x00 0x40000>;
    dr_mode = "peripheral";
    resets = <0x11 0x22>;  // 复位控制器 + RESET_USB (34)
};
```

**复位位定义验证**：
- 从内核头文件确认：`RESET_USB = 34 (0x22)`
- 复位控制器 phandle：`0x11`
- 参考其他外设（audio-controller）的 resets 配置

## ⏸️ 未完成的工作

### 1. DTB 应用到运行设备（受阻）

**阻塞原因**：
- Armbian ophub 的 DTB 加载机制特殊
- DTB 不在标准文件系统位置（/boot 为空）
- 无法在运行时热替换设备树（无 kexec、无 overlay 支持）
- DTB 可能嵌入在 U-Boot 或内核 Image 中
- 直接修改 EMMC 风险高且位置不明

**尝试的方法**：
1. ❌ 查找 /boot 目录 - 为空
2. ❌ 搜索 DTB 文件 - 未找到
3. ❌ kexec 热重启 - 不支持
4. ❌ configfs overlay - 不支持
5. ❌ 驱动 unbind/bind - 仍然失败
6. ❌ 搜索 EMMC 中的 DTB - 超时或位置不明

**结论**：在运行设备上无法安全应用 DTB，需要通过构建流程集成。
